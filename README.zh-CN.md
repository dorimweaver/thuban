# 右枢 · Thuban

[English](README.md) · 中文

**按项目实际需要治理结构、重要文档和上下文入口。**

Thuban 帮助人看懂项目，也帮助下一位智能体找到足以开展工作的资料。根节点提供入口，局部节点随职责生长；目录、文档和导航一起维护。

## 使用

安装后，可以直接说：

| 请求 | 行为 |
|---|---|
| `右枢` / `右枢一下` / 明确要求完整治理 | 理解当前项目，完成可恢复的本地结构与文档治理，验证结果 |
| `右枢一下这个子项目` | 聚焦指定范围，检查受影响的上级入口 |
| `右枢，只看不改` | 只读检查与建议 |
| `讨论右枢应该怎样设计` | 讨论设计 |

也可以显式调用 `$thuban`。技术名称保持 `thuban`，界面名称为“右枢 · Thuban”，保留自动发现。模型是否正确选择 Skill，应以实际任务验证；明确调用 `$thuban` 可直接指定它。

完整治理会修正过时说明和引用、整理重复内容与历史、调整有依据的目录结构，并维护人类可读的整体框架与重要文件职责。先说明范围与改法，再完成已有授权内的工作。项目明确的局部约束继续有效；外部动作、不可恢复损失、权限与业务目标变更按对应授权处理。

## 节点怎样生长

判断依据是持续的独立工作、独特的局部约定与资料，以及单独入口能否减少接手成本。简单项目可以只保留根节点，复杂项目可分出多个局部节点。职责合并后也可以收缩。

已有 README、操作说明和代码证据优先复用。重要文件数量、分类和目录深度随项目形成。每项事实或规则有明确归属，路由指向负责它的文件。

```text
项目 AGENTS.md → 根 THUBAN.md
                    ├─ 局部 THUBAN.md → 局部资料与操作入口
                    └─ README / 架构 / 重要文件索引
```

## 日常维护与全量治理

接手的智能体在任务完成后维护实际受影响的事实、说明和路由。v2 项目的维护约定也允许在该范围内处理有依据的节点增减与可恢复整理。再次发出“右枢”，则检查完整的可治理目录和重要文档，覆盖现有路由遗漏的区域。

这些动作随任务和调用执行。后台定时检查需要单独的自动化设置。已经满足需要的项目可以零改动结束。

## 包结构

| 文件 | 职责 |
|---|---|
| [SKILL.md](SKILL.md) | 调用含义、范围与授权、核心判断、按需入口 |
| [GOVERNANCE.md](references/GOVERNANCE.md) | 完整治理、目录与文档整理、结果验证 |
| [THUBAN-PROTOCOL.md](references/THUBAN-PROTOCOL.md) | 节点、路由、生长收缩、启动和维护约定 |
| [COMPATIBILITY.md](references/COMPATIBILITY.md) | 旧版本识别、兼容与有范围的迁移 |

项目只保存自己的节点、启动块和资料。通用 Skill 核心留在安装目录，按任务加载所需参考章节。

Skill 由智能体根据名称、描述和当前任务选择。实际使用中出现项目特有的选择要求时，简短记在已有的职责入口。

## 版本与验证

新接入使用 `THUBAN:NODE v2` 和 `THUBAN:BOOTSTRAP v2`。旧项目已有的 Skill 选择约定按兼容说明处理。

已有 v1 项目的窄维护规则和明确审批约定继续有效。更新 Skill 本身不会自动改写项目；扩大维护授权时，先说明具体变更并按已有授权迁移目标范围。

检查重点包括启动是否有效、节点可达、资料职责是否清楚、目录调整后能否正常使用，以及新智能体能否完成代表性接手任务。重复治理应稳定，不靠新增文件或更新时间制造进展。测试结果只代表实际覆盖的样例。

## 安装

将本目录安装到用户 Skill 目录，例如 `~/.agents/skills/thuban/`，让宿主发现 `SKILL.md`。在现有安装上更新时保留本地修改与回退版本。仓库地址：<https://github.com/dorimweaver/thuban>。
