# Compatibility and migration

The installed Skill owns the reusable mechanism. Projects own their nodes, bootstrap, documents, and local policy. Updating this package does not itself migrate projects or authorize scanning unrelated roots.

## Versions

| Surface | v2 behavior |
|---|---|
| `THUBAN:SOURCE v2` / `THUBAN:PROTOCOL v2` | Reusable Skill implementation; stays in the installed package |
| `THUBAN:NODE v2` | Same basic sections as v1; root Maintenance can authorize affected-scope structural upkeep |
| `THUBAN:BOOTSTRAP v2` | Routes ordinary work to the project contract and recognizes the full-governance invocation |
| `THUBAN:SKILLS v1` | Legacy project choices: Default selects, Candidate proposes a trial, Avoid records a contextual mismatch. Preserve effective choices; consolidate useful exceptions into their existing owner during authorized cleanup. |

v1 nodes remain readable. Their narrow Maintenance and project-specific approvals continue to apply. The new global Skill does not silently enlarge them. Existing node content remains useful evidence, including when an upgrade is deferred.

## Migrating an authorized project

Inspect only the named roots and their relevant instruction chain. Classify nodes/bootstraps as compatible, v1 migration candidates, malformed/unknown, or excluded. Review inherited and nested constraints as well as markers.

A migration may change node/boot markers and the root Maintenance contract while preserving project ownership, protected records, and independent local constraints. Show the exact authority change; obtain authorization if the user has not already approved that change. A generic repair request does not erase an existing specific approval gate. Already approved migration work continues without another confirmation.

Use the [Node protocol](THUBAN-PROTOCOL.md) v2 contract only in the scope that adopts it. Update matched bootstrap blocks rather than stacking rules. Migrate the connected ownership tree together, or keep an explicitly bounded v1 child under its narrower contract; route to it without claiming that the whole tree has upgraded.

Back up affected files, reconcile effective legacy startup/maintenance conflicts, update consumers, and validate scope plus task recovery. Malformed/duplicate/unknown markers require inspection before choosing a replacement range. Leave compatible unrelated projects unchanged. A broader core change in the future bumps only the affected contract markers and defines its migration.
